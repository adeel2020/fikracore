The 3-Tier Evidence Lifecycle

Why raw INFO/WARNING telemetry must never jump directly into an Incident or Hypothesis.

Tier 1: Raw Evidence Zero Interpretation

What the network emitted directly

Alarms, metric values, logs, traces, event notifications, interface counters. Emitted continuously by OSS, Kafka, and network elements.

INFO: UPF session cleanup task increased interval
WARN: Interface N3 packet retransmission rate = 1.8%
Tier 2: Emerging Evidence (The Bridge) Contextual Significance

Evidence that has acquired operational relevance

Weak correlations, anomaly sequences, spatial relationships, and temporal co-occurrences.

FikraCore statement: "This is not yet an incident, but this sequence of INFO + WARNING + metric deviation is becoming operationally significant."
Tier 3: Validated Evidence Causally Grounded

Checked against the operational investigation

Evidence that formally substantiates or contradicts a hypothesis, confirms a network condition, or establishes an explicit causal edge.

✔ Supports H1 (N3 Transport Buffer Saturation confirmed via diagnostic probe)
✖ Disproves H2 (UPF hardware resource starvation ruled out)
